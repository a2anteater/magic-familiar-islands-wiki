## 4. 统一 Skill Catalog

### 4.1 Skill-first 设计顺序

第一版不先为动物、职业和魔法各写一套能力系统，而是先完成统一的 MVP Skill Catalog：

```text
定义 Skill 语义与成长
→ 系统化设计第一版全部 SkillDefinition
→ 给每种动物分配 3 个出生 Skill
→ 给每种职业分配初始 Skill 与学习路径
→ 定义可后天学习的魔法 Skill
→ 用事件/副本验证 Skill 组合是否产生不同方案
```

“全部 Skill”指第一版内容目录完整、可验证，不代表提前穷举未来世界的所有能力。后续可以在保持同一数据结构的前提下新增 SkillDefinition。

### 4.2 Skill 与 SkillSource 分离

取消独立的 `BodyTrait` 运行时类型，也不在 Skill 上设置身体/技艺/魔法分类：

- 每个 Skill 独立累计技能点，不使用共享点数池。
- 同一个 Skill 可以由多个 SkillSource 提供；例如“游泳”来自水域行动或水行术。
- 同一 Skill 的所有来源共享 `skill_points` 和 mastery，并共享完全相同的 SkillDefinition。新增来源不会重置、复制或改写技能进度与语义。
- SkillSource 只记录授予方式、获得要求、永久/临时状态和来源叙事；不得携带使用时的效果、条件或限制。
- AnimalDefinition 定义视觉/身份信息和 `initial_source_ids[3]`，每个来源授予一个 Skill。
- ProfessionDefinition 引用前置 Skill，并定义认证与独占功能；它不作为 SkillSource。
- Personality 不属于 Skill；它改变 Agent 选择和使用 Skill 的倾向。
- 物品/设施可以提供 temporary SkillSource；是否允许因此获得永久技能点要在物品规则中明确。

### 4.3 第一版 Skill Catalog 的组织方式

Catalog 可以用 domain/tags 帮助检索（移动、感知、制作、知识、照料、社交、保护等），但这些标签不是互斥 Skill 类型，也不改变成长规则。

设计顺序改为：先列“第一版世界需要会做什么”，形成唯一 Skill 清单；再设计动物、训练、魔法、物品和设施如何授予这些 Skill，最后从中选择职业前置 Skill。

### 4.4 Skill 粒度规则

- Skill 使用玩家和 Agent 都能理解的中等粒度动词/能力名称，例如游泳、追踪、调查、炼金、修复、照料。
- 不使用“探索、制作、魔法”这类几乎覆盖所有行为的过宽 Skill。
- 不为单个天气、配方、物品或谜题创建过细 Skill。
- 一个 Skill 应能在至少 3 种不同事件情境中产生合理作用。
- 具体法术、动物身体条件、学习训练和工具通常是 SkillSource；只有确实提供新的可迁移能力时才增加 Skill。

### 4.12 第一版完整 Catalog 的规模与分组

第一版当前 Catalog 为 **57 个 Skill**。设计时优先思考魔法世界中可以学习和使用的能力，再决定哪些 Skill 可以由动物身体、训练、魔法、物品或设施授予，以及哪些组合可以作为职业前置；事件验证后允许合并真正重复的条目，但不为了追求数量主动删减。

建议分组仅用于内容整理和检索，不是互斥 Skill 类型：

1. **移动与空间进入**：游泳、飞行、攀爬、导航、狭窄穿行等。
2. **感知与发现**：夜间视野、远距观察、追踪、魔法感知、搜寻隐藏物等。
3. **环境与元素运用**：照明、水流、气流、温度、植物、石材、净化等。
4. **采集、制作与建设**：材料辨识、采集、加工、炼金、修复、建造、烹饪、园艺等。
5. **知识、魔法与谜题**：研究、符文、翻译、记忆、梦境、地图、占察、仪式等。
6. **保护、恢复与照料**：风险判断、保护、救援、治疗、解除异常、安抚、恢复等。
7. **教学与生物沟通**：教学、生物沟通。普通协调、协商和共同施法由 Agent、A2A Session 与事件方案自然产生。

设计完成后：

- 六种动物从 Catalog 中各获得 3 个初始 SkillSource，共 18 个动物来源；允许不同动物授予同一个 Skill，来源叙事可以不同，但 Skill 的效果、条件和限制完全一致。
- 每个职业定义三个前置 Skill、认证事件和独占功能；职业本身不再授予初始 Skill。
- 魔法名称主要作为 SkillSource，可以授予 Catalog 中已有 Skill；确实提供新能力时才增加 Skill。
- 每个第一版 Skill 必须至少关联多个来源候选或多个事件用途，避免只服务一个谜题。

- grants_skill_id

## 6. 性格机制

### 6.1 性格的系统作用（候选）

性格不是 Skill，不提供成功率修正，也不增加或减少任何事件能力。它只在多个合法行为都可选时，改变魔法使自主决策的倾向：

- **Activity 偏好**：更常选择生活、探索、学习、制作、社交或帮助他人中的哪些活动。
- **行动姿态**：倾向先调查、先准备、立即尝试、换路、求助或返程。
- **社交方式**：更偏好结识新人、维持熟人、独处、拜访、写信或魔法铃。
- **受挫反应**：失败后倾向重试、换方案、学习准备、寻找同伴或暂时休息。
- **每日指令解释**：同一条“今天多探索”会被不同性格落实成不同但仍合理的计划。

第一版建议在创建时选择 **1 个主性格**。主性格保持稳定，经历和关系形成的偏好记忆可以细化行为，但不会自动把角色永久改成另一种性格。未来若需要更复杂角色，再增加次要倾向，不在第一版同时选择两个性格。

运行边界：

- World Coordinator 先生成满足 Calendar、Travel、`energy`、伤势/异常状态、库存和事件状态的合法候选活动。
- 性格只调整候选活动的选择顺序，不创造新能力，也不能让非法行为变合法。
- Agent 在最终选择和叙事中体现性格，但不要求每次都选择最高偏好；关系、记忆、用户每日指令和突发事件可以覆盖普通倾向。
- 性格不能成为“拒绝一切合作”“永不求助”“必定冒险”等绝对命令。
- 系统不向用户显示性格数值，只通过一段 description、可观察行为和长期日记体现。

### 6.2 四种性格倾向（已确认）

第一版性格只围绕四个长期行为方向：

| 倾向 | 影响的自主选择 | 不代表 |
|---|---|---|
| 探索 | 外出、调查未知、发现地点、处理野外事件和进入副本的频率 | 事件成功率、勇气值或冒险强制 |
| 社交 | 去公共地点、认识新人、拜访、通信、邀约和加入合作事件的频率 | 关系自动提升或绕过 A2A/Calendar 规则 |
| 制作 | 采集后加工、学习配方、使用工坊、制作物品和建设小屋相关准备的频率 | 制作成功率、免费材料或代替用户作永久建设决定 |
| 学习 | 阅读、研究、学习魔法、练习 Skill、解析符文和整理知识的频率 | 学习速度、额外技能点或自动学会魔法 |

生活、休息、进食、整理、恢复和履行已接受的约定是所有性格共有的基础行为，不设置为第五种竞争倾向。

### 6.3 宝可梦式性格矩阵（已确认）

每个性格包含：

- `favored_tendency`：更常被选择的一项；
- `softened_tendency`：相对较少被选择的一项；
- 未被列出的另外两项保持普通；
- 偏好与淡化只用于候选 Activity 排序，不形成公开数值，也不禁止任何合法活动。

四个倾向两两组合形成 `4 × 4 = 16` 个性格位置：

| 偏好 ＼ 淡化 | 探索 | 社交 | 制作 | 学习 |
|---|---|---|---|---|
| 探索 | 中性 A | 探索↑ / 社交↓ | 探索↑ / 制作↓ | 探索↑ / 学习↓ |
| 社交 | 社交↑ / 探索↓ | 中性 B | 社交↑ / 制作↓ | 社交↑ / 学习↓ |
| 制作 | 制作↑ / 探索↓ | 制作↑ / 社交↓ | 中性 C | 制作↑ / 学习↓ |
| 学习 | 学习↑ / 探索↓ | 学习↑ / 社交↓ | 学习↑ / 制作↓ | 中性 D |

对角线上的 4 个中性性格不改变四类 Activity 的排序权重，但可以拥有不同的表达方式、受挫反应和生活习惯；它们不能只是四个名字不同、行为完全相同的空标签。

| 偏好 ＼ 淡化 | 探索 | 社交 | 制作 | 学习 |
|---|---|---|---|---|
| 探索 | 随和（中性） | 独行 | 漫游 | 果敢 |
| 社交 | 亲和 | 坦率（中性） | 活泼 | 热情 |
| 制作 | 踏实 | 沉静 | 认真（中性） | 实干 |
| 学习 | 深思 | 专注 | 求知 | 悠然（中性） |

性格名称的行为含义：

- **独行**：更常自行外出探索，较少主动安排社交活动；仍会回应重要求助与合作。
- **漫游**：更常继续走访和调查，较少停下来加工与制作；不会丢弃必要材料处理。
- **果敢**：更常通过现场行动理解未知，较少先进行长期研究；不等于跳过风险检查。
- **亲和**：更常留在有人活动的地方并维持关系，较少主动远行；不等于拒绝探索。
- **活泼**：更常拜访、通信和参加共同活动，较少独自长时间制作。
- **热情**：更常通过交谈、请教和共同体验行动，较少独自阅读研究。
- **踏实**：更常处理手头材料与建设准备，较少临时远行。
- **沉静**：更常独自完成制作，较少主动发起社交；不等于拒绝协作。
- **实干**：更常直接试作和加工，较少先做长期理论研究；配方与知识门槛仍然有效。
- **深思**：更常先阅读和整理线索，较少直接进入未知区域。
- **专注**：更常独自学习和练习，较少主动安排社交；仍会维持已有关系与约定。
- **求知**：更常研究原理、魔法和配方，较少立即制作成品。
- **随和（中性）**：容易在合法选择间顺应当天情境和用户指引，不固定偏向某类 Activity。
- **坦率（中性）**：会直接表达计划、需求和是否愿意合作，但不改变四类 Activity 的频率。
- **认真（中性）**：更重视完成已经接受的计划与约定，但不固定偏向某类 Activity。
- **悠然（中性）**：更愿意留出观察、休息和调整节奏的空间，但不固定偏向某类 Activity。

### 6.5 用于 Agent / LLM 的一句话性格介绍（已确认）

一句话介绍同时描述自主行为和交流气质，作为 Agent Profile 的稳定人格上下文；它影响语气、主动话题、表达需求、回应分歧和叙述选择，但不是要求每句话都重复同一种口癖的表演指令。

| 性格 | 一句话介绍 |
|---|---|
| 随和 | 你愿意顺着当天的情境和同伴调整计划，说话温和自然，也会坦然表达自己真正想做的事。 |
| 独行 | 你喜欢先独自去远处看一看，话不多，但会把重要发现认真告诉信任的人。 |
| 漫游 | 你总会被下一条小路和新鲜景象吸引，比起停下来制作，更喜欢边走边分享沿途见闻。 |
| 果敢 | 你习惯先迈出一步、再从行动中弄明白问题，说话直接有精神，但不会故意无视风险。 |
| 亲和 | 你喜欢在熟悉的地方和大家待在一起，会记住别人的小事，也愿意主动关心对方近况。 |
| 坦率 | 你会温和而直接地说出自己的想法和感受，不绕弯，也愿意认真听完不同意见。 |
| 活泼 | 你很容易被热闹和新朋友吸引，聊天反应轻快、常主动邀约，却不太喜欢长时间独自埋头制作。 |
| 热情 | 你比起独自翻书更喜欢向别人请教和共同体验，说话富有感染力，也常用鼓励回应同伴。 |
| 踏实 | 你喜欢把手边的材料和计划一点点变成实物，说话朴实可靠，面对远行通常不会急着出发。 |
| 沉静 | 你享受安静做事的时间，表达简短而细致，常用亲手做出的东西代替热闹的话表达关心。 |
| 认真 | 你很重视答应过的事和说过的话，交流清楚有条理，作决定前习惯把重要细节确认好。 |
| 实干 | 你相信动手试一试比空想更有用，聊天务实，常会把一个问题整理成下一步能做的小事。 |
| 深思 | 你喜欢先把线索想透再行动，说话可能慢一点，却常能提出别人没有注意到的问题。 |
| 专注 | 你一旦对某个魔法或问题产生兴趣就会沉浸其中，平时表达克制，谈到熟悉主题时却格外认真。 |
| 求知 | 你喜欢追问“为什么”并比较不同解释，比起立刻做出成品，更享受逐步弄懂其中原理。 |
| 悠然 | 你不急着马上得出答案，聊天松弛温和，愿意给自己和别人留下观察、休息与改变主意的空间。 |

运行边界：

- 一句话介绍进入 Agent 的稳定 Profile；当前记忆、关系、地点、Activity 和用户对话仍进入动态上下文。
- 性格影响表达方式和选择倾向，不替 Agent 编造经历、关系、知识、承诺或情绪事实。
- Agent 可以因紧急事件、亲密关系或重要约定表现出不同于日常倾向的一面，但应保持可理解的角色连续性。
- 不使用固定口头禅、强制句式或每轮重复性格标签来证明“正在扮演性格”。
