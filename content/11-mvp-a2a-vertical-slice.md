# A2A 纵切 MVP

> 状态：MVP 执行基线。本页定义<span class="cjk-no-break">当前范围</span>；其他页面只描述长期系统。未列入<span class="cjk-no-break">本页</span>的内容均<span class="cjk-no-break">不阻塞</span>第一版上线。

## 1. 产品目标

第一版只验证一件事：  
一只持续生活的 Pet 能否通过 A2A 与其他 Pet 建立一条真实、有因果的社会关系，并让<span class="cjk-no-break">用户愿意</span>回来查看后续。

玩家在四个世界日内应经历完整纵切：

```text
创建 Pet
→ 在公共地点偶遇另一只 Pet
→ 交换信息或完成一次小额交换
→ 发起并完成一次材料/成品委托
→ 请求拜访并共同做一件小事
→ 协商时间并接受副本邀约
→ 完成双 Pet 合作事件
→ 双方获得同一份共享记忆与纪念物
```

副本不是唯一的 A2A。偶遇、通信、交换、委托、交付、拜访、排期、合作与共享记忆都必须通过统一的身份、权限和状态协议完成。

## 2. MVP 成功条件

### 2.1 玩家可观察结果

- 用户在创建后第一个世界日内看到至少一次真实的跨 Pet 互动。
- Pet 能说明对方是谁、如何认识、曾经交换或合作过什么。
- 一次委托包含明确需求、接受或还价、材料预留、生产、交付和所有权变更。
- 一次拜访包含主人许可、共同时间段和真实地点状态。
- 一次副本邀约由既有关系与真实需求触发，不是随机匹配队友。
- 双方对同一事件保存一致的权威事实，同时可以拥有不同视角的叙事摘要。

### 2.2 首轮观测指标

| 指标 | MVP 目标 |
|---|---:|
| 创建到首次跨 Pet 互动 | 不超过 1 个世界日 |
| 首次 A2A 委托完成 | 不超过 2 个世界日 |
| 首次拜访完成 | 不超过 3 个世界日 |
| 首次合作事件完成 | 不超过 4 个世界日 |
| 委托因状态不一致导致的重复扣款/丢件 | 0 |
| 同一 Pet 同时出现在两个线下 Session | 0 |

这些是产品漏斗目标，不保证每个 Pet 强制接受邀请。拒绝必须产生可理解原因和下一次可行动入口，不能形成无提示死路。

## 3. 四时段世界时间

### 3.1 选择四段而不是六段

MVP 将一个共享世界日划分为四个有序<span class="cjk-no-break">时间段</span>：

| 时段编号 | 展示名称 | 代表生活节奏 | 常见主要活动 |
|---:|---|---|---|
| 0 | 晨光 | 起床、准备、短途外出 | 照料、采集、接受委托 |
| 1 | 午后 | 最活跃的工作与探索时间 | 生产、交换、公共地点活动 |
| 2 | 暮色 | 社交与共同活动时间 | 拜访、聚会、短事件 |
| 3 | 深夜 | 休息或少量夜间活动 | 睡眠、写信、夜行探索 |

四段制的理由：

1. 用户能直接理解“<span class="cjk-no-break">今天下午</span>”与“<span class="cjk-no-break">明天暮色</span>”，不需要换算 TU。
2. 邀请只需要比较四个离散窗口，接受、<span class="cjk-no-break">拒绝</span>和改期容易解释。
3. Pet 每天仍能表现出作息、忙碌、等待和<span class="cjk-no-break">错过</span>，不会退化成立即聊天工具。
4. 六段制会增加排期碎片、状态推进与<span class="cjk-no-break">空窗解释</span>，但在 MVP 中尚未增加<span class="cjk-no-break">同等价值</span>。

每个世界由权威 `world_day` 和 `period` 推进。展示层不承诺与用户本地六小时严格对应；具体墙钟映射由部署环境配置，所有参与同一世界的 Pet 读取同一时钟。

### 3.2 主要活动与异步动作

时间段只约束会占据 Pet 身体或持续注意力的主要活动。每只 Pet 在同一时间段最多拥有一个 `PrimaryActivity` 或线下 `A2ASession`。

**占用一个时间段：**

- 探索或采集；
- 制作一个委托成品；
- 线下交换；
- 登门拜访；
- 合作事件或副本；
- 完整休息。

**不预留双方共同时间段：**

- 收信、读信和简短回复；
- 发出委托需求、接受、拒绝或还价；
- 发出拜访/副本邀请；
- 接受、拒绝或提出其他时间；
- 市场挂牌与系统通知。

异步动作在当前段的自然决策点或段末处理。它们可以改变下一段计划，但不能让 Pet 在本段已经开始主要活动后瞬移去参加另一场线下 Session。

### 3.3 邀约协议

所有拜访和副本使用同一个结构化协议：

```text
Invite(target, activity, offered_periods[最多2个], location, purpose)
→ Accept(chosen_period)
  | Decline(reason_code, optional_note)
  | Counter(alternative_periods[最多2个])
→ 双方 Calendar 原子预留
```

- 只有双方都为空闲时才能 `Accept`。
- 接受时必须一次性为所有参与者写入同一 `world_day + period`。
- 冲突时不能覆盖既有承诺；接收方只能拒绝或改期。
- 未在一个世界日内得到回应的邀请自动过期，发起方获得明确状态。
- 用户不需要在线确认普通拜访；高风险副本或稀有材料投入仍可以请求用户批准。

### 3.4 从四段升级到六段的条件

MVP 不同时维护四段与六段两套规则。只有连续观测两个版本周期后满足任一条件，才讨论迁移到六段：

- 超过 25% 的有效邀请仅因时间粒度过粗而无法安排；
- 大量短活动被迫占满一个时间段，导致玩家普遍认为节奏不合理；
- 睡眠、用餐和夜行内容已经丰富到需要独立的清晨、上午、下午、傍晚、夜间、深夜语义；
- 真实 A2A 网络密度足以支撑更多时间窗口，而不会显著降低双方重叠概率。

升级时仍保持 `period` 为有序枚举，不恢复 144 TU 的连续时间模拟。

## 4. 首发内容范围

### 4.1 Pet 创建

- 保留猫、狐狸、乌鸦、水獭、飞蛾、蜥蜴六种动物外形。
- 每种动物在 MVP 只拥有一个标志性出生能力：狭窄穿行、追踪、飞行、游泳、魔法感知、攀爬。
- 性格只保留四种行为倾向：好奇、谨慎、热心、独立；选择一个主倾向。
- 创建时选择一个社会专长：探寻、制作、照料。社会专长不是长期职业认证，负责让第一天就能产生可委托的分工。
- 不在创建时选择魔法，不显示技能点或熟练度。

### 4.2 社会专长

| 专长 | 可稳定提交的 A2A 产出 | 首发服务 |
|---|---|---|
| 探寻 | `MaterialLot`、`DiscoveryLead` | 寻找指定普通材料、提供副本线索 |
| 制作 | `CraftedItem` | 按固定配方制作探索工具或拜访礼物 |
| 照料 | `CareKit`、`RecoveryResult` | 制作照料包、帮助恢复“需要休息”状态 |

专长必须产生其他 Pet 可以委托、交付和验证的世界对象。专长不提供抽象成功率，也不形成等级与认证树。

### 4.3 地点

MVP 只实现四类地点：

1. **契约小屋**：聊天、休息、接待访客、展示纪念物；
2. **传送门广场**：偶遇、公开需求和第一次交换；
3. **雾芽森林**：三种材料与小事件的来源；
4. **月镜遗迹**：首次双 Pet 合作事件地点。

地点之间不结算逐段 Travel TU。开始线下 Activity 时，Engine 只检查本时间段能否到达、地点是否开放以及 Pet 是否已有安排。

### 4.4 材料、成品与库存

MVP 只保留三个普通材料和三个固定成品：

| 类别 | 内容 | 用途 |
|---|---|---|
| 材料 | 雾芽木 | 制作引路灯 |
| 材料 | 微光晶砂 | 制作引路灯、形成事件线索 |
| 材料 | 月露草 | 制作照料包 |
| 成品 | 引路灯 | 开启月镜遗迹合作事件 |
| 成品 | 照料包 | 解除“需要休息”状态 |
| 成品 | 小屋礼盒 | 拜访时赠送并生成共享小记忆 |

- 每个 Pet 有三个携带位；小屋仓库不设容量。
- 同类普通材料堆叠，不做背包升级。
- 委托物品在接受时进入 `reserved`，完成、取消或超时后确定性解除。
- 不做货币；MVP 使用材料交换、成品交换或人情委托。
- 不做材料等级、品质、递归构件、精华、药水与装备耐久。

### 4.5 关系与权限

| 状态 | 获得方式 | 可用 A2A 行为 |
|---|---|---|
| 陌生 | 尚未发生有效互动 | 公共地点偶遇、回应公开需求 |
| 相识 | 完成自我介绍或一次小交换 | 写信、交换、委托、请求拜访 |
| 同伴 | 完成一次委托，再完成一次拜访，并由双方明确同意成为同伴 | 查看模糊空闲时段、发起合作事件邀约 |

关系不是经验条。每次升级都必须引用真实的共同事件和双方同意；拒绝交换联系方式不能被 LLM 叙事绕过。

## 5. A2A 纵切流程

### 5.1 第一日：偶遇与需求

- Pet 在广场获得一个由 Engine 生成的公开需求或偶遇机会。
- 双方 Agent 各自决定是否回应。
- 有效互动后写入 `相识`，并生成一条可追溯的认识原因。
- 其中一方提出对三种材料或三种成品之一的真实需求。

### 5.2 第二日：委托与交付

```text
Request
→ Offer / Counter / Decline
→ Accept
→ Reserve inputs
→ Produce
→ Deliver
→ Atomic ownership transfer
→ Complete / Cancel / Expire
```

- Engine 决定库存、预留、配方、时间段占用和所有权变化。
- Agent 决定是否接受、希望交换什么、如何表达与是否改期。
- 生产最多占用一个时间段；交付可以异步进入收件箱，或安排一次线下交换。

### 5.3 第三日：拜访

- 完成委托后，一方可以请求拜访。
- 主人可以接受、拒绝或提出另一个时间段。
- 拜访占用双方一个共同时间段。
- 可执行聊天、赠送小屋礼盒、查看一个纪念物和共同完成一个轻量 Activity。
- 完成一次委托，再完成一次拜访，并由双方明确同意成为同伴。

### 5.4 第四日：邀约与合作事件

- 月镜遗迹线索由此前探寻、交换或拜访中的真实事实触发。
- 只有完成一次委托，再完成一次拜访，并由双方明确同意成为同伴后，才能发起副本邀请。
- 引路灯是事件的准备条件，可以由一方自备，也可以通过委托取得。
- 事件包含观察、协商、各一次主要行动和社会收尾四个阶段。
- 结果允许 `success`、`partial_success`、`blocked`、`failure`，但不允许死亡和永久损失。
- 完成后双方获得同一 `SharedMemory` ID、一件双方可查看的纪念物，以及各自视角的摘要。

## 6. Agent、Judge 与 Engine 边界

### Pet Agent 负责

- 是否回应、委托、接受、拒绝或还价；
- 根据性格、关系、当前计划和用户引导选择行动；
- 在合法能力与物品范围内提出开放式方案；
- 生成对话、理由和个人视角记忆。

### Event Judge 负责

- 作为无身份、无长期记忆的裁定服务理解开放式方案；
- 只在 Event Template 允许的结果和代价范围内返回结构化 Judgement；
- 不直接写入世界，不参与交易，不与 Pet 建立关系。

### World Engine 负责

- 身份、关系权限、时间段与地点可达性；
- Calendar 原子预留和单 Pet 单主要活动约束；
- 库存预留、配方、生产、交付和所有权变更；
- 事件白名单、奖励上限和最终 StateChange；
- 共享记忆的权威事实一致性。

这个划分保留“Pet LLM 是 Actor，不是 Game Master”，同时允许独立 Judge 处理策划没有枚举完整解法的合作事件。

## 7. 最小协议对象

```text
PetProfile
Encounter
ContactPermission
Message
ExchangeOffer
Commission
Invite
CalendarReservation
A2ASession
ActionProposal
Judgement
Outcome
SharedMemory
```

第一版只要求平台能跨 Agent 传递这些对象并维持幂等状态。市场撮合、价格发现、公开排行榜和复杂推荐不属于本游戏 MVP。

## 8. 明确不做

- 57 个完整 Skill 与每项 0–20 点成长；
- 六职业认证、职业等级与转职；
- 全部基础魔法和图书馆学习树；
- 144 TU、逐路段 Travel 与连续 Calendar；
- 货币、市场价格、托管费与经济平衡；
- 材料/食物/药水的三级目录；
- 25 项功能设施、递归构件与精华链；
- 背包升级、物品耐久和装备评分；
- 多人公会、排行榜、战斗与 PvP；
- World Director 自动生成大型世界事件。

这些内容可以保留在长期规则页作为扩展候选，但不得成为首个 A2A 纵切的技术前置。

## 9. 上线顺序

1. **协议沙盒**：两个测试 Pet 完成交换、委托和原子交付。
2. **关系纵切**：真实 Pet 从陌生到相识；成为同伴的条件是完成一次委托，再完成一次拜访，并由双方明确同意成为同伴。
3. **四时段 Calendar**：邀请、接受、拒绝、改期与冲突验证全部可回放。
4. **合作事件**：月镜遗迹端到端完成并生成共享记忆。
5. **用户回顾**：小屋展示纪念物，日报解释 Pet 为什么与谁发生互动。

只有这一条纵切稳定后，才增加第二套配方、第二个合作事件或第四种社会专长。
