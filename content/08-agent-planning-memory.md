# Agent 目标、每日计划与记忆

> 状态：已确认方向。本页补充拆分前讨论稿尚未纳入的 Agent 决策规则。

## 1. 单一线性主目标

第一版中，每只魔法使同时只有一个活跃的长期主目标。完成当前目标后，系统才会推进下一个目标。这样可以避免 Agent 在大量物品、设施和技能之间无目的发散，也让用户能理解它为什么寻找某种材料。

主目标由确定性的目标定义描述：

- 完成条件；
- 依赖的设施、物品、知识或关系；
- 每项依赖的已知获得来源；
- 当前世界状态中已经满足和仍然缺少的部分；
- 可执行行动及其固定 TU 成本。

LLM 不负责发明目标依赖、物品来源或时间成本。

## 2. 每日计划循环

每天开始时采用同一个顺序：

1. World Engine 检查昨天的主目标是否完成；
2. 未完成时，Goal Resolver 计算当前缺口和魔法使已知的获取线索；
3. Calendar/Route 查询返回今日可用时间、地点开放情况和每项行动的 TU；
4. Agent 根据性格、职业、经历、用户宏观指令和当前状态，制定具体的 `DailyPlan`；
5. World Engine 校验计划是否可达、是否超时、物品与设施是否满足；
6. Activity 执行后更新世界状态；事件只在需要开放式判断时唤醒 LLM Judge；
7. 次日重新检查目标并重排，不要求机械执行昨天未完成的步骤。

```mermaid
flowchart LR
  A["新的一天"] --> B["Engine 检查主目标"]
  B --> C["解析缺口与已知线索"]
  C --> D["查询 TU、路线与 Calendar"]
  D --> E["Agent 生成 DailyPlan"]
  E --> F["Engine 校验并执行 Activity"]
  F --> G["更新世界状态与记忆"]
  G --> A
```

## 3. Agent 得到的计划简报

Agent 不需要把全世界目录放进 Prompt。它只接收当天与主目标有关的最小简报：

- 当前主目标与进度；
- 最多若干个未满足依赖；
- 自己已经知道的来源和联系人；
- 今日 Calendar 空档；
- 候选行动的准确 TU、路程与必要条件；
- 当前精力、状态、背包与关键物品；
- 用户今天的一个柔性宏观指令。

当缺少物品时，Engine 根据内容数据查找来源；Agent 只决定今天具体采用哪条已知路径。未知来源不会凭空进入简报，Agent 可以安排调查、询问、图书馆研究或拜访。

## 4. 记忆分层与每日刷新

“每天刷新”只指工作记忆，而不是清空角色记忆。

| 记忆层 | 内容 | 生命周期 |
|---|---|---|
| 稳定档案 | 动物、性格、职业、已学 Skill/魔法、长期偏好 | 持久 |
| 世界事实 | 已知地点、配方、来源、设施、规则 | 由 World State 持久保存 |
| 关系记忆 | 认识的人、共同经历、承诺与联系方式 | 持久并按重要性压缩 |
| 情节摘要 | 已完成事件、关键失败、未解决线索 | 持久摘要 |
| 今日工作记忆 | 今日计划、临时观察、当前 Activity 上下文 | 每日重建 |
| Event Context | 当前事件中的参与者、事实、行动与 Judge 结果 | Session 结束后归档摘要 |

新的一天由 Engine 从稳定数据和最新世界状态重新生成今日工作记忆。这样既控制 Prompt 长度，也不会让魔法使每天“失忆”。

## 5. 决策边界

- Engine 决定：目标依赖、来源查询、TU、路线、Calendar 冲突、库存、状态和结算。
- Agent 决定：今天优先做什么、采用哪条已知路径、是否邀请朋友、如何表达和调整计划。
- LLM Judge 决定：开放式事件中方案是否合理，以及成功、部分成功、失败或阻塞的叙事裁定。
- 用户决定：每日宏观倾向、永久家园建设、稀有资源使用和关键职业确认。
