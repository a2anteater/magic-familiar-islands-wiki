## 2. Action、Capability 与检查规则语言

### 2.1 基础 Action 分组（初稿）

| 分组 | 代表动作 |
|---|---|
| 生活 | 休息、进食、整理、照料 |
| 移动 | Travel、进入地点、返回小屋 |
| 探索 | 观察、调查、搜寻、追踪、采集 |
| 制作 | 加工、制作、修复、建造、装饰 |
| 成长 | 学习、练习、研究、领悟魔法 |
| 社交合作 | 拜访、通信、邀约、协助、协调、组合能力 |
| 挑战处理 | 保护、营救、安抚、稳定异常、解除障碍、躲避危险 |

### 2.2 非战斗规则

- 不设计战斗型副本。
- 不提供攻击、防御、伤害、战力、装备评分或战斗等级。
- 危险生物和环境问题优先通过躲避、观察、安抚、保护、营救、修复、仪式或多人能力组合解决。
- 副本压力来自时间、路线、信息、材料、设施、体力、状态和协作，而不是削减敌人生命值。
- 失败可以导致疲劳、受伤、材料损失、行程延迟、退出副本或需要再次准备，但不进入战斗结算循环。

### 2.3 精力值与永久安全

世界只保留一个小整数行动资源 `energy`，普通魔法使范围为 `0–3`，厨师职业被动例外为 `0–4`；不建立攻击、防御或战斗伤害数值：

默认 `energy_cap = 3`；正式厨师的职业被动把自身上限提高为 `4`。其他职业与食物不会永久改变基础上限。

| energy | 状态 | 行动边界 |
|---:|---|---|
| 4 | 储备充足 | 仅正式厨师可通过自己的职业上限保持；行动边界与精力充沛相同 |
| 3 | 精力充沛 | 可以正常生活、探索和处理事件 |
| 2 | 正常 | 可以进行所有普通活动 |
| 1 | 疲惫 | 仍可行动，但 Agent 更倾向进食、返程、缩短计划或休息 |
| 0 | 虚弱 | 不能开始探索、制作训练或高风险事件，只能进食、睡觉、交流或请求帮助 |

事件后果：

- 成功通常不扣精力。
- `partial_success` 或 `failure` 可以把 `energy_delta = -1` 作为合理代价，也可以改用材料损失、受伤状态、延误或错过机会；不是每次失败固定扣点。
- `blocked` 不扣精力，因为行动没有真正发生。
- 普通生活与短途 Travel 不自动扣点；长途旅行、连续工作、危险事件和副本可以在有叙事依据时消耗 1 点。
- LLM Judge 提议精力变化，World Engine 验证事件允许的代价范围并把结果限制在 `0–energy_cap`。

恢复规则：

- 普通食物恢复 `+1 energy`；同一用餐时间只能结算一次。
- 厨师专业料理恢复 `+2 energy`，远征口粮在扎营/休息 Activity 中恢复 `+1 energy`。
- 一次完整睡眠恢复至自己的 `energy_cap`；所需 TU 由当前睡眠设施和守护者职业被动共同决定：

| 睡眠设施 | 普通角色完整睡眠 | 守护者完整睡眠 |
|---|---:|---:|
| 基础睡窝 | 48 TU（8小时） | 42 TU（7小时） |
| 一级床 | 42 TU（7小时） | 36 TU（6小时） |
| 二级床 | 36 TU（6小时） | 30 TU（5小时） |
| 三级床 | 30 TU（5小时） | 24 TU（4小时） |

睡眠是连续占用 Calendar 的 Activity。只有完整完成对应 TU 才结算“恢复至 `energy_cap`”；提前醒来或被事件打断时不按比例恢复，也不触发满额恢复。守护者被动固定减少6 TU，并与床设施叠加；24 TU 是第一版任何来源都不能突破的完整睡眠下限。
- 精力为 0 时仍可以进食、睡觉、交流和接受救援，不会死亡，也不会继续降到负数。

精力与状态分离：食物和睡眠恢复精力，但不会自动移除所有状态。一级状态主要改变角色当下的表现与事件语境；二级状态还会产生由 World Engine 执行的行动限制。守护者负责正式治疗，炼金药剂可以按具体配方解除指定状态，但都不直接恢复基础精力。

魔法使**永远不会死亡**。最严重结果是精力归零、受伤、被救援、丢失部分普通材料、行动失败和一段恢复期；稀有纪念物、关系和已学魔法不因一次失败永久消失。

#### 2.3.1 两级状态系统（MVP 已确认）

第一版只使用一级与二级状态。状态等级表示它对角色和规则的影响强度，不与物品、药水、材料或职业的等级直接对应。

**一级状态：叙事与互动状态**

| 状态 | 状态描述 | 系统作用 |
|---|---|---|
| 潮湿 | 毛发、羽翼、衣物或随身物品被水浸湿 | 不产生固定数值或行动惩罚；进入 Agent 与 Event Judge 的 prompt，可能影响对话反应、社交印象和开放式事件裁定 |
| 弄脏 | 身上沾有泥、灰尘、树汁、孢粉等普通污物 | 不产生固定数值或行动惩罚；进入 prompt，其他角色可以注意、询问、帮忙清理或据此改变互动 |
| 害怕 | 因刚经历的危险、异常或陌生环境而紧张不安 | 不强制禁止行动，也不扣减能力；进入 prompt，使角色的表达、选择和 Judge 对方案合理性的判断体现当前情绪 |
| 闻起来奇怪 | 身上带有药剂、植物、史莱姆或异常环境留下的特殊气味 | 不产生固定数值或行动惩罚；进入 prompt，可能被其他角色或生物注意，并成为社交或事件互动的事实依据 |

一级状态的统一边界：

- World Engine 只保存状态名称、来源、开始时间与解除条件，不把它换算成成功率、能力加减或关系数值。
- Agent 生成对话与行动方案、Event Judge 裁定开放式互动时必须看到这些状态，但不能把它解释成未经定义的硬性惩罚。
- 清洗、烘干、换洗、安抚、离开危险环境或其他符合情境的普通 Activity 可以解除对应状态；具体需要的 TU 与条件由状态来源或事件模板给出。

**二级状态：具有硬规则效果的异常状态**

| 状态 | World Engine 硬效果 | 仍然允许的应对 |
|---|---|---|
| 黏附 | 涉及 Travel、移动、搬运的 Activity 额外消耗 `+1 TU` | 可以交流、休息、使用合适的清理/溶解方案，或接受净化与治疗 |
| 中毒 | 普通食物与专业料理暂时不能恢复 `energy`；完整睡眠仍可恢复精力 | 可以返程、睡眠、交流、求助，并使用对应解毒药剂或接受守护者处理 |
| 受伤 | 不能开始高风险探索、家园建造或高强度训练 | 可以返程、进食、睡眠、交流、求助和进入正式治疗 Activity |
| 魔力紊乱 | 暂时不能使用个人的魔法 SkillSource | 动物出生 SkillSource、普通训练来源与不依赖个人施法的行动仍可使用；可以接受魔法稳定、净化或外部协助 |

二级状态的统一边界：

- 二级状态既进入 Agent/Judge prompt，也由 World Engine 在 Activity 合法性、TU、恢复或 SkillSource 可用性检查中执行。
- 同名状态不叠加成多份数值惩罚；再次获得时只更新来源、解除条件或持续时间。
- Event Template 必须明确该事件允许产生哪些二级状态及其解除条件；LLM Judge 只能从白名单中提议状态，World Engine 验证后写入。
- 解除药水可以处理「黏附」「中毒」「魔力紊乱」中配方明确列出的状态，但不能直接移除「受伤」。守护者可以通过医疗包与正式 Treatment Activity 处理职业等级允许的全部二级状态，并独占「受伤」的正式移除。具体药水、医疗包等级与配方在各自物品表定义。
- 二级状态不会导致死亡、永久残疾或永久失去 Skill、职业、关系与重要纪念物。

### 2.4 Capability 与结果检查

事件不预写完整解法表，也不通过属性数字或固定公式结算。采用 **LLM Event Judge + World Engine Guardrails**：

#### LLM Event Judge 负责

- 理解 Agent 提出的开放式方案；
- 结合场景事实、动物身体、性格、职业、魔法、物品、`energy`、伤势/异常状态、同伴协助和此前事件过程；
- 像 D&D DM 一样判断方案是否合理、是否需要代价，以及结果属于：
  - `success`
  - `partial_success`
  - `blocked`
  - `failure`
- 解释为什么，并提出结构化后果。

#### World Engine 负责

- 检查 Judge 使用的物品、能力、地点和参与者是否真实存在；
- 检查 TU、Calendar、`energy`、伤势/异常状态、库存、通信/关系权限和 Event 状态；
- 限制奖励、材料消耗、状态变化和事件持续时间；
- 禁止死亡、凭空创造能力/物品/地点、越权移动、无限奖励或改写已提交事实；
- 将合法裁定作为 StateChange 原子提交；不合法的裁定返回修正，而不是写入世界。

#### Event Template 只定义“问题空间”

事件模板应包含：

- 场景与隐藏事实；
- 事件目标和风险；
- 当前可观察信息；
- 允许改变的状态范围；
- 奖励/损失上限；
- 禁止结果；
- 结束与超时条件；
- 给 Judge 的裁定原则。

模板不列出完整的 A/B/C 解法。炼金师可以用溶解剂，具备记忆读取的魔法使可能尝试与藤蔓的记忆沟通，水獭可以调整月光蛙的位置，多个 Agent 也可以提出策划未预写的组合方案。

建议的结构化裁定：

```text
Judgement
- verdict
- rationale_summary
- facts_used
- capabilities_and_items_used
- costs_and_time
- consequences
- proposed_state_changes
- narrative_facts
```

LLM 直接拥有 `success / partial_success / blocked / failure` 的结果裁定权；World Engine 只做硬边界验证、要求修正和提交。

### 2.5 裁定记录与回放

- 每次裁定必须保存 Judge 输入所引用的世界状态版本、观察、Action Proposal、相关能力/物品/状态、模型与 Judge 规则版本。
- 保存完整结构化 `Judgement`，包括 verdict、理由摘要、代价、后果和建议状态变化。
- World Engine 保存验证结果、被拒绝/修正的字段以及最终提交的 StateChange。
- 回放时不重新调用 LLM；把已经验证的 Judgement 作为输入重新执行 World Engine 验证/提交。
- 确定性保证是“同一个有效 Judgement 在同一世界版本上产生相同 StateChange”，不是“LLM 每次生成相同裁定”。

### 2.6 统一 Skill / Capability 模型

世界中的 Skill 不区分 Physical、Technique 或 Magic 类型。Skill 定义“会做什么、在什么条件下可用、效果和限制是什么”；动物、职业、魔法、物品、设施和事件是不同的 SkillSource，只定义“为什么以及如何获得”。

```text
Skill
- id / 名称
- 语义描述
- 可以尝试的 Action / 问题领域
- 使用条件
- 通用语义边界
- 明确限制
- 参考案例（帮助 Judge 理解，不构成完整解法表）
- mastery：初学 / 熟练 / 精通
- skill_points：0–20

SkillSource
- source_id / source_name
- grants_skill_id
- acquisition_kind：animal / training / learned_magic / item / facility / event
- provenance_description：为什么通过该来源获得 Skill，只用于内容表达与追溯
- acquisition_requirements：取得该来源需要满足什么条件，只在授予时检查
- grant_mode：permanent / temporary

AgentSkill
- agent_id / skill_id
- skill_points / mastery
- source_refs[]
- learned_at / evidence_refs
```

定性熟练阶段：

- **初学**：处理常见、低风险情形，需要标准条件和完整准备。
- **熟练**：可以处理更复杂环境，或减少材料/时间代价。
- **精通**：允许创造性用法、指导/协助同伴、参与大型仪式或副本关键节点。

能力允许拥有可见的 `skill_points`，但技能点只用于阶段成长，不进入攻击、防御、战力或成功率公式。

建议采用累计制：

```text
学会能力：初学，0 点
累计 10 点：熟练
累计 20 点：精通
精通后封顶，不继续形成无限等级
```

- 用户可以看到当前点数和距离下一阶段的进度。
- 技能点来自实际使用、专项练习、设施、材料、导师/同伴和事件/副本里程碑。
- LLM Judge 判断一次经历是否构成有意义的技能使用或突破，并提出技能点；World Engine 验证能力真实存在、事件已提交、奖励没有重复、单日/单事件上限合法后再写入。
- 初学、熟练、精通改变适用范围、复杂度、材料/时间代价与协作能力，不直接换算成固定成功率。
- 重复执行没有新情境的简单动作不能无限刷点。

技能点结算规则：

- 真实探索/事件中有意义地使用能力：`+1`；
- 完成一次完整专项练习：`+1`；
- 复杂事件、合作或副本关键突破：`+2`；
- 指导同伴或从导师处完成一次有效学习：通常 `+1`；
- 部分成功或失败如果产生真实新经验，可以 `+1`；
- `blocked`、`rejected` 或纯叙事提及不获得点数；
- 同一事件节点、同一能力只结算一次；
- 普通使用/练习每项能力每天最多 `2` 点；副本里程碑每节点只结算一次。

统一模型的意义：

- 动物只决定出生时拥有的 3 个 SkillSource，不决定永远只能做什么。
- 职业、魔法、物品或设施可以提供相同或新的 Skill。
- 技能点属于 Skill，不属于来源；多个来源共享同一条 0–20 成长轨迹。
- 同一个 Skill 在相同 mastery 下始终具有完全相同的使用条件、效果与限制，不能因来源不同而改变语义。
- SkillSource 只在获得、失去或追溯 Skill 时使用；LLM Judge 裁定 Action 时读取 SkillDefinition、mastery 和世界状态，不选择“更有利的来源版本”。
- 如果一种来源需要更窄的效果、更特殊的限制或不同的行动方式，它必须授予另一个 Skill，而不是给既有 Skill 增加来源特例。

示例：

```text
Skill：「游泳」

水獭来源：「水域行动」
- 出生获得
- 说明水獭为什么出生即会游泳

猫来源：「水行术」
- 后天学习
- 说明猫通过学习魔法获得游泳
```

两者最终都拥有同一个「游泳」Skill，并在使用中累积同一类技能点。在相同 mastery 下，两者可尝试的行动、条件和限制完全一致。如果设计上需要一种“只能在水面踏行、不能潜水且需要持续专注”的法术，它应成为独立 Skill，而不能作为「游泳」的受限来源。
