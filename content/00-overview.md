## 0. 已确认的设计原则

1. **事件采用开放式 LLM 裁定，事实必须经过 World Engine 验证并提交。** LLM 像 D&D DM 一样判断开放方案；代码守住世界硬边界、资源预算和权威状态。
2. **动物 = 出生能力分布**：决定创建时天然拥有哪 3 个统一 Skill，不改变 Skill 本身的语义。
3. **性格 = 决策策略**：改变行动权重、风险偏好和求助/重试倾向，不直接决定成功。
4. **职业 = 学成后的专业资格**：由前置 Skill 与认证获得，解锁单一职业独占的强功能与社会分工。
5. **魔法 = 习得能力**：主要由经历、练习和关系形成，不在创建时全部固定。
6. **基础世界可独立运行，专业成果依赖合作**：普通生活和探索不被职业锁死；长期、可交易和跨 Agent 的专业成果可以要求特定职业。
7. **每项内容都必须兑现机制作用**：没有纯标签式动物、性格、职业或物品。
8. **时间、位置、能力、库存与事件结果属于 World Engine 权威状态。**
9. **第一版先证明世界本身成立**：单个魔法使能够生活、行动、旅行、处理事件和形成记忆。

## 1. 世界基础体验与核心生活循环

### 1.1 待确认的体验主轴

产品由三个相互支撑的体验支柱构成：

1. **生活**：魔法使有自己的日程、偏好、巢穴和日常节奏；没有重大事件的一天也成立。
2. **探索**：地点、环境、材料、事件与谜题让动物身体、职业、物品和魔法获得实际用途。
3. **合作**：魔法使通过各自能力互补，一起处理更复杂的事件与副本；合作是世界内容，不等于重新实现通讯服务。

三者不是并列菜单，而是同一个循环：生活产生动机和准备，探索产生材料与经历，合作突破单个魔法使的能力边界；成果再回到生活空间和长期成长。

### 1.2 核心生活循环

```text
魔法使生活并形成目标
→ 用户与魔法使准备物品、魔法和日程
→ 单独探索或与其他魔法使合作
→ 处理环境事件、委托或副本节点
→ 带回材料、物品、记忆和魔法线索
→ 用户建设/装饰/升级小屋
→ 小屋提供外观、舒适度和新功能
→ 魔法使练习并学习新魔法
→ 解锁更远地点、更复杂方案与多人副本
→ 回到新的生活循环
```

循环中的关键因果关系：

- **材料有出处**：必须来自地点、事件、职业制作、委托或合作成果。
- **建设有选择**：用户决定材料优先投入外观、舒适度还是功能空间。
- **小屋有作用**：既是用户表达空间，也是恢复、制作、学习和保存经历的系统入口。
- **魔法有经历**：学习来自材料、设施、练习、导师/同伴与副本经历，不只来自抽象等级。
- **合作有必要性**：更复杂内容允许多种组合解，但不同身体/职业/魔法能显著降低成本与风险。

### 1.3 用户每日宏观指令

用户每天可以向自己的魔法使下达 **1 个宏观指令（Daily Guidance）**，例如：

- 今天多探索；
- 今天多认识其他魔法使；
- 今天多学习魔法；
- 今天留在家里休息；
- 今天优先采集/制作；
- 今天尝试与朋友合作。

宏观指令影响当日剩余自主决策的权重，不直接生成 Activity、不绕过 Calendar/Travel/能力/关系权限，也不保证一定发生对应结果。若当天没有合法机会，魔法使应保持自主并在回顾中解释原因。

宏观指令是**明显但不强制的柔性权重**。建议决策优先级为：

```text
世界硬规则与用户 constraint
> 已接受的 Calendar 承诺
> 安全、疲劳、受伤与基本生活需要
> 当日宏观指令
> 性格、长期目标与即时偏好
```

宏观指令未完成不构成失败，也不返还或累积“指令次数”；日报应说明它如何影响了选择，以及为什么没有执行。

待讨论：下达/替换时间、类别词表和具体权重。

### 1.4 活动密度、风险与成长节奏

- 日常生活是底色，不强制每天发生大型事件。
- 普通探索应在单次外出中产生一个可讲述的小结果：材料、线索、记忆、关系进展或设施目标。
- 合作事件与副本频率低于普通生活/探索，但产出更稀有材料、魔法线索和共同记忆。
- 战斗不是基础循环；风险主要表现为时间、疲劳、受伤、材料消耗、失败、放弃和错过安排。
- 长期成长由 **小屋建设 + 魔法学习 + 地图发现 + 合作能力** 共同构成，避免只剩单一等级线。
