## 9. 物品、资源与制作循环

### 9.1 货币与交易方向（已确认）

世界保留一种通用货币，用于市场定价、异步交易和职业委托，但不把积累财富设为 Agent 的成长目标或幸福数值。材料、装备、设施、Skill、关系和经历仍是实际成长内容。

- 熟人之间可以送礼或直接交换物品。
- 所有魔法使都可以使用集市的公开挂牌、收购订单与职业委托；这些是 Economy Engine 的基础功能，不需要商人职业。
- Economy Engine 负责价格范围、库存预留、货币/物品原子交换和交易契约，LLM 不能直接改写余额或物品所有权。
- 稀有任务物、关系纪念品和指定关键材料可以设为不可交易。

### 9.2 双层资金权限（已确认方向）

| 资金 | 控制者 | 允许用途 |
|---|---|---|
| 日常零钱 | 魔法使在预算内自主使用 | 食物、普通补给、小礼物、低价材料和常规服务 |
| 家园储蓄 | 用户控制 | 装备、稀有材料、高价值药剂、职业委托、设施和永久建设 |

Agent 购买流程：

```text
Agent 提出 PurchaseIntent（需求、目标商品、最高预算）
→ Economy Engine 检查用途、权限、余额、重复持有、价格范围和商品可用性
→ 合法时原子提交货币与物品转移
```

Agent 不因余额增加而自动追求财富，也不能为了花完预算而购物；自主购买必须服务于当前生活需要、已选择计划、明确礼物意图或职业生产需求。

### 9.4 第一版物品分类（候选）

推荐所有物品归入以下十类；类型决定堆叠、使用、交易、损坏和权限规则，不使用一个万能 `Item` 依靠自然语言猜行为：

| 类型 | 代表内容 | 核心用途 | 默认规则 |
|---|---|---|---|
| 建造原料 `raw_material` | 当前已定义的初阶 5 种、中阶 4 种、高阶 3 种材料 | 融合为同级家园构件，也可用于交易和其他职业生产 | 每一级全部材料共同进入一张固定构件配方；只有 0 级简易工作台能直接使用原料建设 |
| 魔物素材 `monster_material` | 史莱姆凝胶、共鸣核心、空间残留等 | 魔法精华、炼金、装备与特殊设施输入 | 通过驱散、收容、净化或解决敌对魔物事件取得；不来自普通动物狩猎 |
| 加工材料 `processed_material` | 木板、布卷、药粉、金属锭，以及一级至三级家园构件 | 制作输入、工匠打造、小屋建设和设施升级 | 家园构件每级只有一种通用成品；入库时默认进入用户保留状态 |
| 魔法精华 `magic_essence` | 一级、二级、三级魔法精华 | 为具有魔法功能的设施、装备、炼金和仪式提供能量输入 | 由同级建造原料、魔法植物和史莱姆素材按固定递归配方融合；权限随炼金师职业等级提升 |
| 食材 `ingredient` | 植物、果实、菌类、谷物和调味素材 | 0级基础食物与厨师1–3级料理 | 可堆叠、可交易；第一版取消普通动物狩猎与渔获，暂不做实时腐坏计时 |
| 消耗品 `consumable` | 普通食物、专业料理、远征口粮、药剂 | 恢复精力、净化、环境准备 | 使用后减少数量；必须满足使用场景与每日/事件限制 |
| 装备与工具 `equipment` | 探索工具、采集器具、防护用品、功能配件 | 提供合法行动入口、降低 TU/材料/风险或临时 SkillSource | 不提供攻击/防御数值；使用定性完好状态，由工匠正式修复 |
| 知识物 `knowledge_item` | 教材、配方、食谱、蓝图、地图记录 | 解锁 Knowledge 或学习入口 | 阅读/登记后写入 Knowledge；不能仅因持有就自动知道内容 |
| 家园物 `home_item` | 家具、装饰、设施模块、建筑构件 | 小屋外观、储存、通信、制作、学习和交通功能 | 永久摆放/建设由用户确认；普通装饰可由 Agent 提议 |
| 关键与纪念物 `key_memory_item` | 事件信物、关系纪念品、遗迹钥匙、唯一收藏 | 推进事件、保存经历和表达关系 | 默认不可出售、分解或被普通失败永久丢失 |

物品共同边界：

- 物品效果必须是明确 StateChange、权限或条件，不使用“看起来更强”但无法验证的描述。
- 装备主要改变可做什么、所需 TU/材料或 Event Judge 可接受的方案，不产生战力评分。
- 配方、蓝图、地图与教材属于 Knowledge 载体；物品实例和已登记 Knowledge 分开保存。
- 普通失败可以损失部分可替代材料或消耗品，但不会随机删除关键物、关系纪念品、已学 Skill 或职业资格。
- 第一版不做重量、格子俄罗斯方块和逐件实时腐坏；携带能力与远征准备采用后续定义的简化规则。

### 9.5 建造原料的三档结构（修正确认）

材料等级表示获取难度、用途范围与投入权限，不表示同一种材料存在 `+1/+2` 品质，也不直接换算成装备战力：

| 等级 | 获取方式 | 主要用途 | 消费权限 |
|---|---|---|---|
| 初阶 | 第一日开放区域的普通采集、基础事件、市场常备供应 | 普通食物以外的日常制作、基础工具、简单修复、家具与练习 | Agent 可在普通消耗预算内自主使用 |
| 中阶 | 深入 checkpoint、特定环境窗口、职业采集/分解、较复杂事件 | 功能装备、职业工具、通信/学习模块和更完整的修复 | 用于职业订单或永久物品时进入计划；大型投入需用户确认 |
| 高阶 | 副本、合作事件、区域关键发现或高级职业产出 | 家园关键设施、传送门、特殊装备和长期项目 | 始终由用户确认；普通失败不会随机永久丢失 |

所有建造原料实例使用固定 `material_id` 与等级。现有 5/4/3 清单整体属于“建造原料线”；其中微光晶砂、回声晶片、月镜晶核等指定材料同时进入同级魔法精华配方，因此玩家需要在构件、设施指定原料与精华之间做真实取舍。

第一版不再建立独立“魔法材料”资源线。魔法精华的三类固定来源是：现有建造原料、分级魔法植物和分级史莱姆素材。植物与魔物素材清单在后续章节逐级设计。

### 9.10 魔物与魔物素材目录（MVP 已确认）

魔物是敌对或失控的魔法聚合体、拟态体与异常魔具，不属于可创建的六种动物，也不作为普通生态动物处理。第一版没有攻击、防御、HP 或击杀结算；Event Judge 可以通过引开、限制、拆解、安抚、净化、修复环境或合作驱散等方案解决事件。

| 2 | 镜壳拟态体 / 镜壳拟态片 | 会模仿箱子、石块或入口外观的反光魔法聚合体。 | 细节观察、改变光线、识别不一致、温和拆解 | 映像、伪装、反射和防护准备类药水/装备 |
| 2 | 迷途灯灵 / 灯灵余烬 | 会用错误光路把旅者引向岔路的失控引导火光。 | 校正路线、遮光、重写引导符文、净化 | 照明、方向感、驱雾和导航辅助药水 |
| 3 | **空间史莱姆 / 空间史莱姆核心** | 身体内部折叠着不稳定短路径，会让附近物品突然换位。 | 空间稳定、设置锚点、分步收容、关闭异常 | 三级魔法精华固定输入；空间稳定与传送设施 |
| 3 | 星门寄生体 / 星门寄生晶壳 | 附着在旧传送结构上吸收路径回响的晶质聚合体。 | 切断能量、修复门框、诱导脱离、封存 | 传送门维护、路线锚定和高级空间药水/装备 |

素材只在对应魔物事件得到合法解决后由 World Engine 结算；LLM 不能因为故事中“打了一下”就凭空生成掉落。普通动物不会生成魔物素材，也不会被作为食材或制作原料。

### 9.11 药水的统一输入结构（已确认方向）

每张药水配方固定使用三类同级输入：

```text
指定植物/食材 × 配方数量
+ 指定魔物素材 × 配方数量
+ 指定建造原料 × 配方数量
→ 对应等级 PotionBatch
```

- 药水等级不能超过炼金师职业等级；一级药水要求职业1级炼金师，二级要求职业2级，三级要求职业3级。
- 三类输入必须是配方列出的具体 `item_id`，不能仅凭“同等级”任意替换；LLM 可以提出新配方研究，但 World Engine 在配方被正式发现前不会提交产物。
- 药水主要处理净化、异常、环境准备、感知和行动条件，不直接恢复基础 `energy`，也不代替守护者的正式治疗。
- 同一种植物可以进入食谱、精华或药水，魔物素材也可能进入精华、药水或装备；同一物品实例被消耗后不能同时用于另一条生产线。

药水的 MVP 功能分为两类：

1. **能力药水**：使用后临时提供一个现有 Skill 的 SkillSource，持续一个指定 Activity 或一个 Event；不创造药水专属能力，不增加永久技能点，也不能计入职业认证条件。使用者已有该 Skill 时沿用自己的 `skill_points` 与 mastery；从未学过时按 0 点初学使用。效果不叠加，本次临时使用也不产生技能点。
2. **解除药水**：一次性解除配方明确指定的一级状态，或「黏附」「中毒」「魔力紊乱」中的指定二级状态；它不能解除「受伤」，不补充 `energy`，也不能以“万能净化”为名移除配方没有列出的状态。

能力药水只提供尝试行动的能力入口，不能临时抬高角色的 mastery，也不能绕过地点、知识、工具、材料、Calendar、职业独占功能与 Event Judge 裁定。药水等级用于限制配方、炼金师职业等级和可提供的能力范围；各级能力药水的具体目录与持续时间随药水表定义。

#### 9.11.1 一级药水（5 种，MVP 已确认）

一级药水由职业1级以上炼金师在一级炼金台或公共余烬工坊的合格场地制作。每张配方每批产出1瓶，消耗2 TU；所有投入均为一级物品。

| 药水 | 类型 | 固定配方 | 使用效果 |
|---|---|---|---|
| 清洁泡泡剂 | 解除药水 | 清露叶 ×1 + 魔帚鬃束 ×1 + 雾胶树脂 ×1 | 一次解除使用者当前拥有的「潮湿」「弄脏」「闻起来奇怪」状态；不会解除害怕或任何二级状态 |
| 安心莓露 | 解除药水 | 雾莓 ×1 + 躁动孢粉 ×1 + 云绒纤维 ×1 | 一次解除「害怕」状态；不会强迫角色改变观点、同意请求或遗忘造成害怕的经历 |
| 微光眼露 | 能力药水 | 月露草 ×1 + 普通史莱姆凝胶 ×1 + 微光晶砂 ×1 | 临时提供「夜间视野」SkillSource，持续一个 Activity 或一个 Event |
| 轻步药水 | 能力药水 | 云穗麦 ×1 + 魔帚鬃束 ×1 + 雾芽木 ×1 | 临时提供「平衡」SkillSource，持续一个 Activity 或一个 Event |
| 暖流药水 | 能力药水 | 暖芯根 ×1 + 普通史莱姆凝胶 ×1 + 青纹石 ×1 | 临时提供「热量操控」SkillSource，持续一个 Activity 或一个 Event |

一级药水统一边界：

- 每瓶只能由一个角色使用一次，结算后物品实例被消耗。
- 能力药水必须在相关 Action 裁定前使用，不能在结果已经提交后追溯补用。
- 药水提供的来源在对应 Activity 或 Event 完成、退出或超时后立即移除。
- 五张配方恰好覆盖全部五种一级植物与五种一级建造原料；素材覆盖不代表未来新增配方必须继续保持一一对应。
- 是否允许同一角色同时维持多个不同的能力药水效果，等二级与三级药水目录完成后统一决定；同一 Skill 的重复药水效果始终不叠加。

#### 9.11.2 二级药水（4 种，MVP 已确认）

二级药水由职业2级以上炼金师在二级炼金室，或公共余烬工坊对应等级的职业工位制作。每张配方每批产出1瓶，消耗4 TU；所有投入均为二级物品。

| 药水 | 类型 | 固定配方 | 使用效果 |
|---|---|---|---|
| 解缚溶剂 | 解除药水 | 浮云瓜 ×1 + 共鸣史莱姆核心 ×1 + 浮光木芯 ×1 | 一次解除「黏附」；不会返还该状态生效期间已经消耗的额外 TU |
| 清毒药剂 | 解除药水 | 雾眠菇 ×1 + 灯灵余烬 ×1 + 月镜银砂 ×1 | 一次解除「中毒」；解除后后续食物可以正常恢复 `energy`，但不会补发中毒期间已经失去的恢复量 |
| 魔力定序剂 | 解除药水 | 共鸣铃花 ×1 + 共鸣史莱姆核心 ×1 + 回声晶片 ×1 | 一次解除「魔力紊乱」；恢复个人魔法 SkillSource 的可用性，但不会改变任何 Skill 的点数或 mastery |
| 水行药水 | 能力药水 | 月镜莲藕 ×1 + 镜壳拟态片 ×1 + 月藤韧丝 ×1 | 临时提供「游泳」SkillSource，持续一个 Activity 或一个 Event |

二级药水沿用一级药水的一次性、使用时点、临时来源移除和同一 Skill 不叠加规则。四张配方恰好覆盖全部四种二级植物与四种二级建造原料；共鸣史莱姆核心因同时用于二级精华和两种药水，形成明确的资源取舍。

#### 9.11.3 三级药水（目录延期）

第一版暂不设计三级药水的具体名称、效果与配方。当前内容没有足够明确的高阶副本或事件场景，提前指定短距转移、生命感知、梦境行走等药水容易形成没有实际用途的成品。

三级炼金室与三级药水的数据接口继续保留，但只有在新增内容同时明确以下信息后，才反向设计对应药水：

- 需要解决的具体场景与问题；
- 不使用药水时仍然存在的其他合法方案；
- 药水应提供的现有 SkillSource 或可解除状态；
- 为什么一级或二级药水无法满足该场景；
- 对应三级植物、魔物素材、建造原料与制作成本。

三级药水不得只因为“等级更高”而临时提高 mastery、扩大数值或成为万能解法。

### 9.12 食物等级与通用规则（MVP 已确认）

| 食物等级 | 制作者 | 所需设施 | 每批制作 TU | 主要价值 |
|---:|---|---|---:|---|
| 0 级 | 任意魔法使 | 家园自带简易炉台或安全营火 | 1 | “烤一切”：把一个可食用素材做成一份当场食用的简单食物，恢复 `+1 energy` |
| 1 级 | 职业1级以上厨师 | 一级厨房 | 2 | 可储存/交易的家常料理，每批通常2份，每份恢复 `+1 energy` |
| 2 级 | 职业2级以上厨师 | 二级厨房 | 4 | 专业料理每份恢复 `+2 energy`；开放可在远征扎营使用的正式口粮 |
| 3 级 | 职业3级厨师 | 三级厨房 | 6 | 多人宴席、恢复餐和大批量高级料理 |

统一边界：

- 0级“烤一切”不是食谱：投入任意一个 `ingredient`，产出一份简单烤食；即使使用高级食材也只得到0级效果。成品必须在本次用餐/休息 Activity 中食用，不能储存、交易或登记为远征口粮。
- 1–3级食物必须拥有正式 `RecipeKnowledge`，严格消耗固定 `item_id` 和数量；LLM 不能把相近食材临时替代进去。
- 普通单人/小份用餐消耗1 TU；多人宴席创建2 TU `MealSession`。远征口粮在扎营/休息 Activity 中结算，不在不可中断事件里瞬间使用。
- 同一用餐窗口只结算一次 energy 恢复；重复进食不能在同一个窗口堆叠恢复。
- 第一版不创建寒冷、水域、声音、梦境等正式食物准备状态。Event Judge 可以把近期吃过的合适料理视为叙事证据，但 World Engine 不保证额外效果，也不持久化状态。
- 食物只能恢复到食用者自己的 `energy_cap`；不会治疗伤势、中毒或持续异常。
- 第一版不做逐件腐坏计时；0级烤食通过“必须当场食用”维持与正式料理/口粮的区别。

### 9.16 食物配方覆盖与职业价值

- 12种已确认植物/食材全部至少进入一张正式食谱；月露草、共鸣铃花和星露果同时还竞争精华用途。
- 厨师的价值不是简单提高 Cooking Skill：职业开放可储存批次、远征口粮、宴席 Session 和恢复餐等权威对象。
- 低级食材持续进入二、三级食谱，避免职业升级后一级采集与园艺失去需求。
- 高级食物的收益主要是批量效率、社交/远征功能和恢复协作，不继续无限提高 energy 数值。

### 9.17 自上而下的成品设计顺序（已确认）

推荐先定义用户和 Agent 实际使用的成品，再反推配方与低阶材料：

```text
定义成品功能与使用场景
→ 确定由哪个职业/设施制作
→ 确定蓝图、食谱或配方 Knowledge
→ 定义需要的材料标签与等级
→ 回填具体材料和数量
→ 用获取时间、TU 与市场价格验证成本
```

建议设计顺序：

1. **设施模块**：先锁定写信、魔法铃、传送门、厨房、工坊、学习、储存和睡眠等核心功能。
2. **家具与装饰**：区分纯外观、舒适/恢复、展示纪念物和功能家具。
3. **装备与工具**：围绕探索、采集、职业生产、携带与环境应对设计。
4. **食物与厨师料理**：围绕 `energy`、远征口粮、宴席和恢复餐设计。
5. **炼金药剂**：围绕净化、异常处理和环境准备设计，不恢复基础精力。
6. **反推材料与食材**：最后确定每个等级需要多少种、各自进入哪些配方。
