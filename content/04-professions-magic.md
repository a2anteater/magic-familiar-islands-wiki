## 7. 职业资格与专业功能

### 7.1 职业形成与单职业规则（已确认）

职业不是创建时赠送的能力包，而是魔法使学习并证明一组 Skill 后获得的专业资格：

```text
ProfessionDefinition
- profession_id / name / description
- prerequisite_skills[3]
- required_mastery：待确认
- certification_event_id
- exclusive_function_ids[]
- commission_types[]
- knowledge_unlocks[]

AgentProfession
- agent_id
- profession_id：nullable；每个魔法使最多一个
- certified_at
- certification_evidence
- status：active / 待后续定义
```

- 魔法使最初没有正式职业，可以学习任意 Skill、进行普通生活和参加基础事件。
- 满足三个前置 Skill 与职业认证事件后，才能获得职业。
- 每个魔法使最多拥有一种职业；第一版认证后不可放弃或转为另一职业。
- 学会其他职业的前置 Skill 不会获得第二职业，也不会自动获得该职业的独占功能。
- 动物和性格不限制职业选择；它们只影响初始 Skill 与学习/行动倾向。
- 职业描述进入 Agent Profile，影响专业视角、术语和提出方案的方式，但不覆盖性格的聊天气质。

### 7.2 Skill 与职业独占功能的边界（已确认）

职业的价值不能只是三个 Skill 的别名。统一规则为：

- **Skill** 决定“会不会做、能否提出这个方案以及面对多复杂的情境”，例如加工一块材料、寻找线索、理解动物意图或照料伤势。
- **Profession Function** 决定“能否稳定、批量、分级地产出系统认可的结果”，以及是否拥有职业专属被动、事件观察视角和世界对象提交权限。
- **Knowledge / Facility / Recipe** 决定“是否拥有正确知识、工具、场地和材料”。Skill 足够但缺少这些条件时，方案仍会被 World Engine 阻止。
- Skill 可以由所有魔法使学习，职业只能选择一个；同主题 Skill 与职业可以重叠，但职业不能只是同名 Skill 的成功率加成。
- 独占功能由 World Engine 校验 `profession_id`，不能仅靠 LLM 声称拥有，也不能由同名 Skill 绕过。
- 独占功能可以成为特定设施、稀有物品、深层地点或合作项目的硬需求，以形成真实分工。
- 普通生存、基础探索和基础社交不能依赖某个职业，避免世界在职业人口不足时完全停摆。
- 职业产出需要真实材料、Knowledge、设施、TU 和 LLM Judge 裁定；职业资格不是免费成功或无限生产。
- 用户可以委托其他魔法使的职业服务；支付、材料交付和时间安排由物品/委托系统在后续章节定义。

|---|---|---|---|---|

### 7.4 职业独占范围（已确认）

- 非探寻者仍能搜索、导航并偶然发现材料，但不能获得职业性的稳定材料产出、按职业等级开放高等级发现，也不能提交正式资源点或捷径。
- 非炼金师学会精华萃取术后仍能进行一级基础萃取，但不能提交稳定批次、功能药剂、正式分解或二、三级精华。
- 非工匠仍能按固定配方制作一级家园构件并进行临时维护，但不能制造功能装备、正式修复或二、三级构件。
- 非自然使仍能寻找普通食材、照料普通植物和友善接触生物，但不能获得职业性的稳定分级食材产出或创建持续产出节点。
- 非守护者仍能使用急救/治愈/净化 Skill 包扎、稳定或陪伴伤者，但不能制作远征医疗包、创建正式治疗方案或移除职业级持续异常。
- 非厨师只能执行 0 级基础烹饪“烤一切”，制作简单日常食物；不能制作一级至三级专业料理、口粮、宴席或恢复餐。

这些独占功能有意形成跨职业循环：探寻者和自然使带回更多资源，炼金师分解、炼药并提炼高级魔法精华，工匠把物质材料变成高级家园构件与装备，厨师把食材变成精力与远征续航，守护者处理伤势和持续异常。高级魔法设施因此可能同时需要工匠和炼金师的产出。市场挂牌、货币结算、交易托管和委托撮合属于 Economy Engine 的基础能力，不依赖任何职业。Skill 与魔法学习同样保持为通用成长系统，不绑定职业。具体产量、配方、课程和交易规则在后续章节定义。

### 7.5 职业资格与职业等级（修正确认）

职业采用一级、二级、三级，但不增加独立职业经验条。职业等级由前置 Skill、已经提交的职业世界对象和晋级事件共同决定：

| 职业等级 | Skill 条件 | 经历条件 | 解锁原则 |
|---:|---|---|---|
| 1 级 | 三个前置 Skill 均达到 10 | 完成职业认证事件 | 获得正式职业身份、一级产出、职业视角和基础职业被动 |
| 2 级 | 三个前置 Skill 均达到 15 | 完成若干有效职业委托/产出，并通过二级晋级事件；精确数量待平衡 | 获得二级稳定产出与对应设施权限 |
| 3 级 | 三个前置 Skill 均达到 20 | 完成职业大师项目 | 获得三级稳定产出、最高级职业设施权限和完整职业被动 |

认证/晋级事件由 LLM Judge 根据职业方案开放裁定；World Engine 验证 Skill 点数、职业记录、单职业限制、事件完成状态和最终等级写入。职业等级不是第四条成长数值，也不能只靠重复低风险动作升级。

公共基础能力保留两个明确例外：非工匠可以制作固定配方的一级家园构件，非炼金师学会精华萃取术后可以提取一级精华。职业1级在这些领域提供稳定批次、正式记录和其他职业产出；二级、三级构件/精华仍分别要求工匠或炼金师达到对应职业等级。

### 7.6 职业选择权与认证触发（已确认）

推荐流程：

```text
Agent 根据已有 Skill、性格、经历与世界需求形成 CareerAspiration
→ 向用户说明想选择的职业及原因
→ 用户确认这个唯一职业选择
→ 满足三个前置 Skill 熟练条件后创建 CertificationEvent
→ LLM Judge 裁定认证过程，World Engine 验证并写入 AgentProfession
```

Agent 可以自主学习和表达职业愿望，但不能在没有用户确认时提交唯一职业；用户也不能在 Skill 条件不足时跳过学习直接授予职业。

### 7.7 职业稳定性（已确认）

第一版在认证后不可转职：职业决定长期独占功能、工具投入、委托关系和其他魔法使对它的依赖，频繁转职会削弱身份与社会分工。认证前必须向用户明确提示这是唯一且长期的职业选择，并再次确认。

不可转职不限制继续学习其他 Skill 或魔法；它只限制第二职业资格和其他职业的独占功能。未来如果运营中确实需要转职，再单独设计退职、等待期、重新认证与既有委托处理规则，不在第一版预留无成本切换。

### 7.8 用于 Agent / LLM 的一句话职业介绍（已确认）

职业介绍进入稳定 Agent Profile，用来决定魔法使会优先注意哪些事实、使用什么专业词汇以及更容易提出哪类方案；性格介绍继续决定交流气质，两者组合而不是互相覆盖。

| 职业 | 一句话介绍 |
|---|---|
| 探寻者 | 你习惯从路线、地形、遗漏线索和可能的收获观察问题，谈到远行时总会留意是否存在更短或更有价值的路径。 |
| 炼金师 | 你看到材料和异常现象时会自然想到它们的性质、配比、用途以及能否被炼制或分解，并会谨慎说明未知反应。 |
| 工匠 | 你习惯把问题拆成材料、结构、连接方式和损坏位置，讨论方案时常会先确认需要什么工具以及东西能否可靠修好。 |
| 自然使 | 你会留意季节、水域、植物状态和生物留下的痕迹，谈论资源时也会关心它们能否持续生长与再次取得。 |
| 守护者 | 你总会先注意同行者是否疲惫、受伤或处于异常状态，讨论行动时习惯把恢复和安全返程一并考虑。 |
| 厨师 | 你会留意大家的精力、口味和接下来的行程，看到食材时自然会想到怎样搭配成既好吃又能支撑行动的一餐。 |

未获得职业时，Agent Profile 不注入任何职业介绍；职业愿望可以作为动态记忆出现，但不能提前使用职业身份或独占功能。

### 7.9 厨师职业详细规则（已确认）

厨师只有在食物承担明确世界功能时才成立，不以“能做饭”作为唯一价值：

| 项目 | 设计 |
|---|---|
| 前置 Skill | 烹饪、材料辨识、热量操控，均达到熟练 10 点 |
| 独占功能 | **料理与备餐**：制作带正式恢复/远征效果的料理、口粮与多人宴席 |
| 权威世界对象 | `PreparedMeal`、`ExpeditionRation`、`SharedFeast`、`RecoveryDiet` |
| 对其他魔法使的价值 | 延长探索可持续时间、恢复普通疲劳、为多人活动准备补给，并通过宴席创造自然社交场景 |
| 职业被动 | 厨师自身 `energy_cap = 4`；其他职业默认上限为 3 |

职业边界：

- 所有魔法使都可以执行 0 级基础烹饪“烤一切”，产出当场食用、恢复 `+1 energy` 的简单食物，不会因世界里没有厨师而无法生存。
- 只有厨师可以制作一级至三级正式食物、远征口粮、多人宴席和恢复餐；可制作等级不能超过厨师职业等级。
- 一级食物用于稳定日常备餐，二级食物包含恢复 `+2 energy` 的专业料理和远征口粮，三级食物包含多人宴席、恢复餐和大型备餐；具体食谱后续单独设计。
- 食物不能治疗伤势、毒素或其他持续异常，也不能把食用者的数值提高到其自身 `energy_cap` 以上。
- 远征口粮必须在休息/扎营 Activity 中食用，恢复 `+1 energy`；不能在不可中断事件中瞬间使用。
- 多人宴席创建 Meal Session，为参加者按专业料理规则恢复精力并产生共享经历，但不直接增加关系数值或强迫关系变化。
- 恢复餐可以与守护者的治疗方案配合、减少恢复所需的休息 TU，但不能代替守护者处理伤势。

三种恢复产品的分工：

| 来源 | 主要用途 | 使用条件 | 不能做什么 |
|---|---|---|---|
| 厨师料理 | 日常恢复、远征续航、多人用餐 | 需要进食/休息 TU，效果较稳定 | 不治疗伤势和持续异常 |
| 炼金药剂 | 净化、解除特定异常或环境准备 | 可携带，消耗药剂与材料，按物品规则使用 | 不直接恢复基础精力，也不能替代睡眠与长期治疗 |
| 守护者治疗 | 处理伤势与持续异常 | 需要治疗方案、时间和可能的材料 | 不直接补充日常精力，也不是普通补给 |

### 7.10 守护者职业详细规则（已确认方向）

| 项目 | 设计 |
|---|---|
| 前置 Skill | 急救、治愈、净化，均达到熟练 10 点 |
| 独占功能 | 制作分级医疗包，建立正式治疗方案并处理伤势与持续异常；MVP 先开放一级与二级医疗包 |
| 权威世界对象 | `MedicalKit`、`TreatmentPlan`、`RecoveryRecord`、`StatusRemoval` |
| 职业被动 | 守护者自己的完整睡眠固定减少6 TU；与床设施叠加，三级床时为24 TU；只改变速度，不提高 `energy_cap`，也不替别人恢复精力 |

- 急救、治愈、净化 Skill 允许任何魔法使在事件中提出包扎、稳定、安抚或净化方案，并由 LLM Judge 裁定结果。
- 守护者职业负责可携带、可交易、效果稳定的医疗包，以及需要长期写入世界状态的正式治疗与异常移除。
- 医疗包等级不能超过守护者职业等级；第一版的「受伤」只有一种正式状态，不再增加轻伤/重伤数值或伤势等级。
- 守护者睡眠加速与床设施叠加，完整睡眠分别为基础睡窝42 TU、一级床36 TU、二级床30 TU、三级床24 TU；不得再低于24 TU。

#### 7.10.1 Treatment Activity 与两级医疗包（MVP 已确认）

| 医疗包 | 使用条件 | 确定性效果 | Treatment TU |
|---|---|---|---:|
| 基础疗伤包 | 职业1级以上守护者；目标位于家园、中心城镇或 Event Template 标记的稳定安全地点 | 消耗1个医疗包，移除一名角色的「受伤」 | 3 |
| 远征医疗包 | 职业2级以上守护者；目标位于远征营地或安全 checkpoint | 消耗1个医疗包，移除一名角色的「受伤」，并可同时移除该角色「黏附」「中毒」「魔力紊乱」中的一个 | 2 |

医疗包固定制作配方：

| 医疗包 | 固定配方 | 制作者与场地 | 每批产量 | 制作 TU |
|---|---|---|---:|---:|
| 基础疗伤包 | 清露叶 ×1 + 月露草 ×1 + 云绒纤维 ×2 + 雾胶树脂 ×1 | 职业1级以上守护者；简易工作台 | 1 | 2 |
| 远征医疗包 | 基础疗伤包 ×1 + 雾眠菇 ×1 + 共鸣铃花 ×1 + 月藤韧丝 ×2 + 月镜银砂 ×1 | 职业2级以上守护者；一级工坊或公共余烬工坊的合格工位 | 1 | 4 |

二级配方递归消耗一个基础疗伤包，因此从原始材料开始制作一个远征医疗包的最低制作劳动为6 TU。一级工坊在这里仅提供清洁、裁切、封装和登记所需的合格场地，不要求工匠参与，也不把医疗包变成工匠产物。

治疗边界：

- 标准 Treatment Activity 在满足职业、医疗包、地点、目标状态和 TU 条件后由 World Engine 确定性结算，不再要求 LLM 判断是否成功。
- 正在进行的危险 Event、移动途中或未建立安全点时，现场急救仍属于开放式 Action Proposal，由 LLM Judge 裁定能否稳定情况、帮助撤离或争取时间；不能直接冒充标准 Treatment Activity 移除「受伤」。
- 普通魔法使可以使用急救、治愈、净化 Skill 提出帮助，但没有守护者职业和合法医疗包时不能提交正式 `StatusRemoval`。
- 医疗包不会恢复 `energy`。治疗完成后，目标若仍处于低精力状态，必须另外进食、休息或睡眠。
- 医疗包是一次性消耗品；取消尚未开始的治疗不消耗，Treatment Activity 一旦开始即消耗医疗包，中途被打断也不返还。
- 医疗包制作是固定 Recipe Activity：World Engine 验证守护者职业等级、配方 Knowledge、材料、场地与 TU 后确定性提交 `MedicalKit`，不由 LLM 判断是否制作成功。
- 两级医疗包均不需要魔物素材、魔法精华或炼金师产物；其合作需求主要来自自然使提供植物，以及探寻者提供纤维、树脂和矿物材料。
- 三级医疗包的接口保留，但具体效果与配方延期到出现多人救援或高阶恢复场景后再设计，不因职业3级而凭空增加治疗数值。

## 8. 魔法学习系统

### 8.1 魔法与统一 Skill 的关系（已确认）

魔法不是独立于 Skill 的第二套能力树。每个可学习魔法是一个永久 SkillSource，并授予一个统一 Skill：

```text
MagicDefinition
- magic_id / name / one_line_description
- grants_skill_id
- discovery_requirements
- learning_requirements
- required_knowledge_ids[]
- required_materials[]
- required_location_or_facility
- learning_tu

AgentMagic
- agent_id / magic_id
- learned_at / learning_evidence
- source_ref
```

- 新魔法授予尚未拥有的 Skill 时，该 Skill 从 0 点/初学开始。
- 如果 Agent 已经通过动物、训练或其他魔法拥有同一个 Skill，新魔法不会复制技能点、改变语义或叠加效果。
- 魔法名称可以进入 Action Proposal 与叙事，例如“使用水行术”；LLM Judge 和 World Engine 仍按对应 SkillDefinition、mastery 和世界状态裁定。
- 魔法不使用独立攻击力、法力值或成功率数值；施放代价由 TU、`energy`、材料、设施、环境与事件后果表达。
- 学会魔法不等于知道所有用法；Skill 的初学、熟练、精通与 0–20 点仍是唯一成长轨迹。

### 8.2 第一版基础魔法与学习入口（已确认）

```text
Agent 因兴趣、需求或 Daily Guidance 选择一种基础魔法
→ 前往倒悬图书馆取得公开教材
→ 创建 LearnMagic Activity
→ Agent 提出学习方法，LLM Judge 裁定经历与结果
→ World Engine 验证教材、TU 和重复授予
→ 成功时写入 AgentMagic 与永久 SkillSource
```

第一版所有可学习魔法都是普通基础魔法：

- 不设置特殊、稀有、古代或职业专属魔法。
- 所有动物都可以学习所有基础魔法，不设置物种限制或先天适性。
- 所有基础魔法的公开教材都可在倒悬图书馆取得，不要求先在随机事件中发现。
- 学习仍需要实际 Travel 与 Study TU，不能通过打开图鉴立即获得。
- 后续版本可以增加需要事件、副本、遗迹、关系记忆或特殊材料才能发现的特殊/稀有魔法，但不进入第一版。

### 8.3 初始无魔法（已确认）

魔法使创建时不拥有任何魔法，也不在第一天安排强制启蒙事件。动物提供的三个出生 Skill 足以支持初始生活、基础探索、社交和普通事件；魔法不是进入核心世界循环的前置门槛。

第一个魔法没有固定获得时间。Agent 只有在后续生活中因为兴趣、实际困难、Daily Guidance 或与其他魔法使交流而形成学习意愿，才会主动前往图书馆寻找对应教材。

### 8.4 后续魔法学习触发（已确认）

推荐流程：

```text
Agent 因真实经历、兴趣或建议形成魔法学习方向
→ 根据性格、当前困难、Daily Guidance 和长期愿望形成 LearnMagicIntent
→ 前往图书馆取得公开教材并自主安排基础学习
→ 完成 LearnMagic Activity 后获得对应 SkillSource
```

用户可以通过每日宏观指令鼓励学习或建议一个方向，但不能直接把魔法写入 Agent；Agent 也不能在没有教材、TU 和实际学习过程的情况下凭兴趣凭空学会。

### 8.5 魔法数量与学习并发（候选）

推荐不设置“最多掌握几个魔法”的硬上限，也不引入魔法槽位。长期差异由发现机会、学习意愿、所需 TU、材料、设施、Knowledge 和实际练习形成，而不是创建时永久锁死。

为避免短时间批量学习与 Agent 同质化：

- 每个 Agent 同一时间只能拥有一个 active `LearnMagicIntent` / 学习项目。
- 第一版所有魔法使用同一基础学习规则，不设置复杂度或稀有度分层。
- 学习项目可以暂停后恢复，但不能同时从多个项目结算学习成果。
- 已拥有对应 Skill 的魔法不会提供新的功能、点数或 mastery；Agent 默认不为纯重复功能消耗材料和时间。
- 如果同名 Skill 已经由动物或其他魔法授予，魔法图鉴应明确显示“能力已拥有”，避免用户误以为能够叠加。
- 学会魔法后永久保留；第一版不设计遗忘、魔法槽切换或洗点。

### 8.6 图书馆、实践与同伴教学的成长边界（已确认）

三段 mastery 继续使用统一的 `0–20 skill_points`：

| 阶段 | 点数 | 主要成长方式 |
|---|---:|---|
| 初学 | 0–9 | 图书馆阅读、基础练习、普通使用 |
| 熟练 | 10–19 | 真实使用、专项锻炼、生活/探索事件、向更高 mastery 的同伴学习 |
| 精通 | 20 | 长期实践、复杂事件/探险突破或高 mastery 同伴指导后的关键成长 |

图书馆规则：

- 第一次完成对应教材的学习，授予魔法 SkillSource，并从 0 点开始。
- 每次有效图书馆 Study Activity 消耗 4 TU，结算 1 点；Travel TU 另计。
- 同一 Skill 每天最多从图书馆结算 2 点，且与普通使用/专项练习的每日 2 点防刷上限共用，不形成额外点数池。
- 图书馆最多只能把对应 Skill 提升到 10 点。
- 达到 10 点后，继续重复阅读同一本基础教材不再获得技能点。
- 图书馆不会直接把 Skill 提升到精通，也不会提供 10 点以上的被动阅读成长。

从 0 到 10 需要 10 次有效学习，共 40 TU 的纯学习时间，并分布在至少 5 天。使用默认魔法通道时，家园往返图书馆需要 8 TU；若每天在一次行程中连续学习 2 点，五次行程合计再消耗 40 TU，因此完整默认成本约为 80 TU（13 小时 20 分钟）。家用传送门会降低行程部分，不改变学习本身的 4 TU/点。

10 点之后的成长来源：

- 在生活、职业准备、事件或探险中有意义地使用魔法；
- 进行具有新目标、环境或反馈的专项锻炼；
- 在复杂事件或副本关键节点取得突破；
- 向同一 Skill mastery 高于自己的魔法使学习并完成教学/共同练习 Session。

同伴教学边界：教师必须真实拥有同一 Skill，且 mastery 高于学员；拥有「教学」Skill 可以让 Agent 提出更完整的教学方案，但不能直接赠送技能点。所有成长仍遵守每日上限、事件去重和 LLM Judge + World Engine 验证。

### 8.7 第一版基础魔法完整覆盖（已确认）

第一版 57 个统一 Skill 每个都至少配置一个可在图书馆学习的基础魔法来源。魔法只提供获得同一 Skill 的另一条路径，不改变其 SkillDefinition、使用条件、限制、Knowledge/配方/蓝图要求或职业独占功能。

例如：烹饪魔法仍需要食材与食谱，研究魔法不会凭空产生知识，修复魔法仍需要材料和损坏信息；学会打造相关 Skill 也不能在没有工匠职业时提交正式功能装备。
